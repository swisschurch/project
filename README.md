# Swiss Church · 업무 정리

월별 슬로건 · 프로젝트별 업무 · 캘린더를 여러 사람이 함께 보고 고치는 웹앱입니다.
로그인한 뒤 **관리자 승인을 받은 사람만** 내용을 볼 수 있고, 누가 고치든 **모두의 화면에 바로 반영**됩니다.
데이터는 Firebase(Google)에 저장되고, 앱 화면은 `index.html` 한 파일입니다.

## 기능

| 기능 | 내용 |
|---|---|
| 로그인 · 가입 신청 | 각자 아이디·비밀번호를 정해 가입 신청 → 관리자가 **회원 관리**에서 승인하면 사용 가능. 승인 전·거절·사용 중지된 계정은 데이터를 볼 수 없음 |
| 실시간 공유 | 수정하면 다른 사람 화면에 1~2초 안에 반영. 서로 다른 업무를 동시에 고쳐도 충돌 없음. 업무 편집 창에 "마지막 수정: 이름 · 시간" 표시 |
| 프로젝트 (메인) | 우선순위(긴급·높음·보통·낮음) 순 3열 배치, ▲▼로 순서 조정, ★로 중요 표시함에 모음. 제목을 누르면 설명·진행률 펼침 |
| 업무 | 시작 전 / 진행 중 / 완료 / 반려 / 차후 + 기간, 연관 업무 연결. 왼쪽 ⠿ 손잡이를 끌어 순서 변경(휴대폰은 살짝 누른 뒤 끌기). 프로젝트 없는 업무는 "프로젝트 미지정" |
| 캘린더 | 교회 공식 일정 · 부서 일정 · 업무 기간을 골라 보기 |
| 슬로건 | 상단 슬로건 클릭 → 입력. 월 표시(예: 2026년 11월 ▾)를 누르면 지난 달 기록이 펼쳐짐 |
| 언어 | 설정에서 한국어 / English. 입력한 내용도 자동 번역(MyMemory 무료 번역), 편집 창에서 직접 수정 가능 |
| 이월 | 미완료 업무를 다음 달로 복사 (이번 달 기록은 그대로) |

## 처음 설정하기 (관리자 1회, 약 15분)

### 1. Firebase 프로젝트 만들기
1. https://console.firebase.google.com 에 구글 계정으로 접속 → **프로젝트 추가**
2. 이름: `swiss-church` (아무거나) → Google 애널리틱스는 **사용 안 함** → 만들기

### 2. 로그인 기능 켜기
1. 왼쪽 메뉴 **빌드 › Authentication** → **시작하기**
2. **이메일/비밀번호** 선택 → 첫 번째 스위치(이메일/비밀번호)만 **사용 설정** → 저장
   (앱은 아이디를 내부적으로 `아이디@users.swisschurch.app` 형식으로 바꿔 씁니다. 실제 메일은 보내지 않습니다.)
3. Authentication › **설정 › 승인된 도메인**에 사이트 주소 도메인 추가 (예: `swisschurch.github.io`)

### 3. 데이터베이스 만들기
1. **빌드 › Firestore Database** → **데이터베이스 만들기**
2. 위치: `europe-west6 (Zürich)` 추천 → **프로덕션 모드**로 시작
3. 만들어지면 **규칙** 탭 → 내용을 모두 지우고 이 저장소의 [`firestore.rules`](firestore.rules) 내용을 붙여넣기 → **게시**

### 4. 앱에 Firebase 연결
1. 프로젝트 개요 옆 ⚙️ **프로젝트 설정** → 아래 **내 앱** → 웹 아이콘 `</>` → 앱 이름 입력 → 앱 등록 (Hosting 체크 안 함)
2. 화면에 나오는 `firebaseConfig = { apiKey: ..., ... }` 값을 복사
3. `index.html` 맨 위 `FIREBASE_CONFIG` 의 빈칸에 붙여넣고 저장(커밋)
   이 값은 공개되어도 괜찮습니다. 데이터는 3번의 보안 규칙(로그인 + 승인)으로 보호됩니다.

### 5. 첫 관리자 만들기
1. 사이트를 열고 **가입 신청**으로 본인 계정을 만듭니다 → "승인 대기 중" 화면이 뜹니다.
2. Firebase 콘솔 › Firestore Database › 데이터 › `users` 컬렉션 → 본인 문서 클릭
3. `status` 값을 `approved`, `role` 값을 `admin` 으로 고칩니다.
4. 사이트 화면이 자동으로 열리고, 상단에 **회원 관리** 버튼이 생깁니다.

### 6. 기존 데이터 올리기
처음 열면 "공유 데이터가 비어 있습니다" 안내가 나옵니다.
- 예전 버전에서 쓰던 내용이 있으면: 예전 버전을 열던 방식 그대로 열고 **설정 › JSON 내보내기** → 새 사이트에서 **JSON 가져오기**
- 같은 브라우저·같은 주소에서 예전 버전을 썼다면 **이 브라우저에 저장된 기존 데이터 올리기** 버튼이 바로 보입니다.

### 7. 사이트 주소 만들기 (GitHub Pages)
저장소 **Settings › Pages** → Branch: `main` / `(root)` → Save → `https://<계정>.github.io/<저장소>/`
(무료 플랜에서는 공개 저장소에서만 Pages를 쓸 수 있습니다. 공개해도 코드만 보이고, 업무 내용은 Firebase에 있어 로그인·승인 없이는 볼 수 없습니다.)

## 사용하는 사람

1. 관리자에게 받은 링크를 엽니다.
2. **가입 신청**: 아이디(영문 소문자·숫자·`._-`, 3~20자), 비밀번호(6자 이상), 이름, 소속 부서
3. 관리자가 승인하면 화면이 자동으로 열립니다. 이후에는 아이디·비밀번호로 로그인.
4. 비밀번호 변경: **설정 › 내 정보 › 비밀번호 변경**

## 관리자

- 상단 **회원 관리**(빨간 숫자 = 승인 대기 인원): 승인 / 거절 / 사용 중지 / 관리자 지정·해제
- **비밀번호를 잊은 사람**: 이메일이 없어 자동 재설정이 안 됩니다. Firebase 콘솔 › Authentication에서 그 사용자를 삭제하고,
  Firestore › `users`에서 그 사람 문서도 삭제한 뒤 같은 아이디로 다시 가입 신청하게 하세요.
- 백업: **설정 › JSON 내보내기** (가끔 받아 두세요)

## 알아둘 점

- 같은 업무 하나를 두 사람이 동시에 고치면 나중에 저장한 쪽이 남습니다. 서로 다른 업무는 문제없습니다.
- Firebase 무료 요금제(Spark) 한도: 하루 읽기 5만 · 쓰기 2만 건. 교회 팀 규모에서는 충분합니다. 카드 등록 없이 무료로 쓸 수 있습니다.
- 자동 번역을 켜 두면 입력 내용이 MyMemory 번역 서비스로 전송됩니다. 원하지 않으면 설정에서 끄세요.
